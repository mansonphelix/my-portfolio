Windows Server: Setting Up Active Directory

Windows Server · 15 min read

What you'll learn

  • Installing Active Directory Domain Services
  • Creating OUs, users and groups
  • Setting up DNS and DHCP for the domain
  • Creating your first Group Policy Object

Active Directory (AD) turns a standalone Windows Server into the identity and policy centre of the organisation. Below is the practical path I follow for a first domain controller in a small or medium environment.

Prerequisites

  • Windows Server (2016 / 2019 / 2022) installed and updated
  • Static IP address on the server
  • Meaningful hostname (e.g. DC01)
  • A domain name you control or an internal name (e.g. company.local or corp.company.com)

1. Install the AD DS role

Open Server Manager → Add Roles and Features → Active Directory Domain Services. Accept the features it pulls in. After installation, promote the server to a domain controller.

2. Promote to domain controller

Choose “Add a new forest” for a green-field install. Enter the root domain name. Set a strong Directory Services Restore Mode (DSRM) password and store it securely.

DNS is usually installed together with AD DS — keep that option enabled.

3. Post-promotion checks

  • Verify the server is in the domain and has a computer account
  • Confirm DNS is resolving the domain and SRV records
  • Check Event Viewer for AD and DNS errors

4. Organisational Units (OUs)

Create a logical OU structure early, for example:

Company
├── Users
│   ├── Staff
│   └── IT
├── Computers
│   ├── Workstations
│   └── Servers
└── Groups
    ├── Security
    └── Distribution

Avoid dumping everything into the default Users container.

5. First Group Policy Object

Create a GPO linked to the Workstations OU that:

  • Enforces a password policy suitable for the organisation
  • Maps a common network drive
  • Sets the default home page or trusted sites if needed

Test with a single pilot computer before wide deployment.

6. Backup and documentation

Enable system state backups (or full server backups). Document the domain name, FSMO roles (on a single DC they are all local), admin accounts, and OU design.

A clean AD structure is easier to secure and much easier to hand over.

Once this base is stable you can add a second domain controller for redundancy, introduce file shares with NTFS + share permissions, and start centralising applications that support AD authentication.
