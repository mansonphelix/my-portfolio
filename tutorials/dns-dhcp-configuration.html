DNS & DHCP Configuration

Windows Server · 13 min read

What you'll learn

  • How to install and configure DNS and DHCP roles on Windows Server
  • Setting up scopes, exclusions and reservations
  • Creating forward and reverse lookup zones
  • Common mistakes that cause name resolution or IP conflicts

DNS and DHCP are the two services users never notice — until they break. A clean, documented configuration prevents the most common causes of slow logons, failed printers, and "server not found" errors.

1. Install the roles

Install-WindowsFeature -Name DNS,DHCP -IncludeManagementTools

After installation, open the management consoles and confirm both roles show as running.

2. Configure DHCP

Create a scope that matches your subnet design:

  • Start / end IP — leave room for static servers and printers
  • Subnet mask and default gateway — usually your router or firewall
  • DNS servers — point clients to your internal DNS servers first
  • Exclusions — reserve the first and last addresses for infrastructure

3. DHCP reservations

For servers, printers, and network cameras, create reservations by MAC address. This keeps IPs stable without hard-coding static settings on every device.

4. Configure DNS

Create a forward lookup zone for your domain and a reverse lookup zone for your subnet. Add A records for servers, printers and infrastructure, then verify resolution from client machines.

5. Common mistakes

  • Clients receiving DNS from the wrong server after a reboot — check scope options
  • Duplicate DHCP scopes across sites or VLANs without relay agents
  • Missing reverse lookup zones, which slow name-to-IP troubleshooting
  • Forgetting to authorize DHCP in Active Directory
If you can ping an IP but cannot resolve its name, DNS is the problem. If you cannot get an IP at all, DHCP is the problem. Start there before you replace cables.

6. Quick checklist

  • DHCP scope with exclusions, gateway and DNS options set
  • Reservations for all known servers and printers
  • Forward and reverse DNS zones created
  • nslookup and ipconfig /all tests from client machines
  • Documented static IP list for auditors and on-call staff
